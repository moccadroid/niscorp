# Haptic Nisc qualification

User-approved strategy, 4 November 2026. Finish the product through explicit contracts and independently judged results, not a target review number. The previous execution engine remains unchanged unless a concrete mechanical defect is demonstrated. No database, controller, speculative adapter framework, execution AI or caller approval step is introduced.

## Acceptance tracks

- **Execution:** validated JSON artifacts execute mechanically through declared operations. Input ownership, cancellation, caller ceilings, current-data reuse, provenance and dependency isolation remain verified.
- **Ownership:** source agents author source queries only; the published Prism agent authors every Prism program; caller/schema author owns the data contract; JSON owns calls, branches, prompts, repair and budgets; Strata owns grammar stamps. No XML authoring exception remains. Native code implements mechanics and contracts, not website/business policy.
- **Usefulness:** automatic public request+URL discovery returns independently source-supported data and reusable artifacts. Known wrong/missing associations do not pass merely because schemas, selectors or model verdicts pass.
- **Honesty:** complete, useful partial, unusable and unresolved are separate outcomes. Negative/unavailable semantic review does not suppress mechanically working data. No blanket rejection, empty-output trick, dropped failure slot, changed caller schema or selective retry can create an apparent improvement.

## Work sequence

1. Freeze baseline source/tests/benchmarks/scripts and current positive/negative evidence.
2. Split XML XPath and mapping authors while keeping one jointly tested candidate. Original XML, actual selected records and real errors remain available to a bounded correction cycle; no ready-before-mapping handoff. Delete composite author registrations/contracts, no compatibility aliases.
3. Audit actual Spiegel/Ruby/timetable failures along source→selection→native input→Prism→review. Distinguish discarded source values, wrong shaping, mistaken reviewer claims, upstream/provider failures and unsupported reader capabilities.
4. Test one generic existing-review context correction at a time on saved bad and successful cases. Use actual 120b after offline input checks. Preserve useful partials; inspect exact requests/responses; revert a change that does not help. No additional judging system, hidden semantic gates or domain-field logic.
5. Establish SQLite static HTTP capability from actual source and target bytes. Do not assume JavaScript/browser necessity or treat placeholder links as archive identity. Any required general reading capability must be separately explicit and tested, not a website workaround.
6. Once focused real-model checks improve, freeze independent qualification contracts and run fresh original 17 tasks × 2 plus agreed real-use cases. Discovery uses the actual library path; returned artifacts execute without AI or manual edits. Report all attempts, source-supported facts/associations, false acceptance, requests/tokens/actual waits/time and changed/added/empty data separately.
7. At substantive checkpoints, independently review ownership/context/quality against the same category meanings. Final offline/package/HTTP-PDF checks and documentation follow. Package move/publication remain separate actions; sibling Nisc workspace is not changed or linked.

## Fixed constraints

Fields and schemas remain dynamic. Caller schemas and explicit false/zero permissions remain authoritative. Configured budgets/limits remain JSON. Original captures, failed trials, credentials and Git history remain. No saved source replaces a live endpoint in the final live batch. Focused saved-source model tests are labeled separately. Source/selector expectations used by grading are never supplied as answers to discovery.
