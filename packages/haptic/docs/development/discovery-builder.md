# Discovery builder and engine grammar

The finished path is **JSON artifact → prepared in-memory engine → result data**. Discovery builds that artifact using a fixed JSON pipeline. TypeScript supplies typed boundaries and mechanical capabilities; JSON owns sequencing, decisions, prompts, limits and repair.

## Fixed pipeline

1. Admit the request and compile a supplied output schema before model/HTTP effects.
2. Declare the strict task action `{requiresNavigation,resultFlow}`. JSON checks offered actions and caller permission; bounded declaration repair cannot increase them.
3. Acquire/traverse admitted frontiers using the existing alias-aware BFS helpers. Formats, permissions and limits remain JSON data.
4. Author the current source component. HTML offers CSS/fields and only a resource reference path for a task-declared processor; source authors never choose processing-flow IDs. standalone XML offers XPath/namespace fields. XML reference following assembles one paired `{xml,mapping}` rule from the XPath source author and the published Prism agent. Each call can inspect only offered sources in its current frontier or propose its component. JSON trials the proposal against original captures and commits mechanical success automatically. A paired XML rule must execute both extraction and mapping before becoming ready. Identified mechanical failures narrow the next component; there is no model finish or arbitrary component routing.
5. Assemble complete captured extraction. Standalone JSON is already native input; XML/HTML supply selected values. Reference tasks compose the existing traversal/resource programs.
6. Use the unchanged caller schema, or call the separate ordinary-schema author. Invalid automatic declarations can receive compilation feedback within the shared allowance. An admitted schema is fixed for subsequent shaping.
7. Invoke the published Prism mapping agent with actual execution examples, the effective schema and JSON-owned requirements; execute its program and return mechanical failure feedback for bounded correction.
8. Review resulting data against the instruction and matching source evidence. Negative feedback can repeat the same fixed source/schema/mapping pipeline within `review.maxRepairs` and remaining allowances. Each author sees its own prior proposals/observations and delivered review feedback; sources are not repeatedly stored in history. Caller schemas stay fixed; automatic schemas can be reauthored in a new pass.
9. Run the fresh complete URL-artifact trial regardless of the semantic verdict. A working artifact returns `ready` with separate review and repair metadata. A failed correction retains the preceding working artifact and its matching schema/verdict. Fresh mechanical failure still prevents publication.

JSON reference and output program authors share the JSON `program-context` message producer. It wraps each offered native value in the actual `{input: value}` execution scope. This replaces separate encoders/headers; it does not wrap runtime values or add a new execution operation. The XML source author sees original XML and emits XPath only. Mechanical selection feeds actual `{url,items}` values through the same shared reference-proposal job to the published Prism agent. JSON tests the pair before readiness; failures can correct either selection or mapping.

Source author feedback has two independent slots: `failure` retains the latest failed candidate's mechanical trial, while `inspection` holds only the latest source observation. Inspection cannot clear a rejection. A new failed candidate replaces the failure and clears the prior inspection; a passing candidate clears both. A new frontier starts empty. A failed paired XML trial adds its actual selected records as `selectedValues`; a rejected trial is not mislabeled as a zero-match result. JSON reference-program feedback keeps its separate existing contract. All transitions and wording are JSON, within the existing observation/input/model allowances.

The shared mechanical `output-source` projection supplies acquired final `resourceUrls` to both captured output authoring and finished artifact shaping. The existing reviewer receives those same URLs and minimal recorded redirect facts through context. This adds no acquisition, model step, URL rewriting or native policy. See [output shaping](output-shaping.md).

`discovery.json` owns this order. Its named helpers are grouped in `discovery-acquisition.json`, `discovery-source.json`, `discovery-output.json`, `discovery-binding.json` and `discovery-model.json`. `mechanical.json` owns execution helpers. Shared JSON helpers calculate model settings, spent budgets and errors once; splitting files does not introduce a new interpreter or change the phase order. The entry composes JSON documents and derived boundary schemas; it is not a native planner/compiler. There is no universal action controller, cross-job prompt replay or model-selected repair routing. Review feedback repeats the fixed author pipeline; it does not selectively route to a supposedly responsible job. That can revisit correct work, but keeps the process explicit and bounded.

## Local job ownership

Task declaration, source authoring, schema authoring and output mapping accept strict named inputs and return their own results. They do not receive or return the root discovery state. The root calls the existing reviewer directly with the final data, result schema and matching evidence, then applies its returned allowance. Accounting receives one allowance plus reported usage and returns one allowance; history helpers receive explicit history/feedback inputs and return history values.

The source job receives one current level, its already materialized frontier, the required task/schema/authority/configuration values, author allowance and history/feedback. Its result contains exactly `{level,part,feedback,allowance,histories,reason}`. Request, inspection and trial helpers receive narrower consumed fields; they cannot reopen global levels, acquisition, the reviewer budget or the last working result. Local retries preserve the same remaining author allowance and the original source indices. The existing shared history helpers expose only the exact job/frontier to models and preserve unrelated history entries.

Traversal owns acquisition, prepared-document identities, levels, frontier/depth, target charges and only the author allowance. Acquisition returns the capture/owned/current-level changes it produces. Advancement returns only `{depth,frontier,hasNext}`. Traversal alone replaces the current level; root alone merges its returned author allowance while retaining the reviewer allowance and output/last-working state. No root state passes through the source job, acquisition or advancement.

Assembly returns its source artifact, native extraction, matching review evidence, resource acquisition and limitation fact. Schema compilation receives the grammar stamp; output binding receives only its shaped flow; captured trials receive only artifact/captures/URL. Fresh verification receives only artifact/URL and returns trial/publication/reason. Root composes these values, renews budgets at the existing bounded review-correction boundary, and retains the last matching working bundle.

Final job success requires its admitted schema or working artifact/completed trial. Intermediate rejected trials remain repair feedback. A literal-null Prism program is valid when the result schema permits its output.

## Model jobs and shapes

Every model job shares the provider-output boundary. JSON profile `outputRejections` declares code/status pairs and correction evidence; `output-rejection.json` selects the evidence with Prism. TypeScript preserves structured provider facts and converts only a match into the existing failed-output protocol. Cortex alone retains the conversation and takes another bounded step. It never accepts rejected reasoning as answer data. All those steps and elapsed time count against the existing author/reviewer allowance; ordinary transport errors do not open another discovery attempt. The default only recognises `output_parse_failed`/400; an empty rule list disables it.

| Job                    | Evidence                                                                                                             | Response                                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Task                   | Original instruction, starting URL, offered result flows and optional caller time                                    | Strict task action                                                                                                             |
| HTML source component  | Current prepared frontier, current rule, caller contract when supplied, permissions and relevant mechanical feedback | Source-only CSS inspection or `{action:"propose",candidate:...}`                                                               |
| Standalone XML source  | Original XML frontier, current XPath rule and relevant mechanical feedback                                           | Source-only XPath inspection or component proposal                                                                             |
| XML reference rule     | Original XML frontier, current paired rule, permissions, trial errors and selected values after failure              | XPath inspection or `{action:"propose",candidate:{selector,namespaces,fields}}`; published Prism writes the mapping separately |
| JSON reference program | Current native JSON values, reference contract and feedback                                                          | Bare Prism config                                                                                                              |
| Result contract        | Original request/time and actual source/extraction capabilities                                                      | Ordinary JSON Schema body                                                                                                      |
| Output program         | Original request, fixed data schema, actual native input and mapping feedback                                        | Bare Prism config                                                                                                              |
| Final review           | Actual shaped data, distinct data contract, matching source evidence and real scope                                  | `{accepted,reason}`                                                                                                            |

Source author contracts do not offer finish, component inspection, value inspection, arbitrary URLs or operation names. Output and all reference mappings use the actual published `@niscorp/prism/agent` definition; local instruction/documentation overrides are not accepted. Its system prompt, schema and documentation are unchanged; the shared runner binds only JSON-owned output strategy and stop conditions. XML source candidates contain no mapping. The published agent receives actual selected records, and the assembled pair must pass the ordinary joint trial. Cortex owns malformed/schema-invalid response recovery; no native validation callback runs trials or chooses repairs.

## Source and trial ownership

Raw HTTP responses live only in `acquisition.sources`; prepared documents live only in `owned`. A level stores `{url,sha256}` identities, not another response or document. A consumer materializes its current view from those owners, and a missing identity fails explicitly. Redirect-only captures remain available for faithful captured trials. Repair reuses those owners and the existing acquisition charges. Completed stage-trial diagnostics retain source URLs, not response bodies.

Named Zod phase contracts validate each consumed slice and each produced value. Source jobs, their local request/inspection/trial helpers, acquisition and advancement have closed inputs and owned outputs. The traversal frame is also closed and excludes root output/reviewer state. Root composition retains unrelated owners explicitly instead of forwarding them through these jobs. Success outputs guarantee their required fields; source success requires a mechanically ready level, while intermediate rejected trials remain repair feedback. Admitted schemas/programs are not reinterpreted by another native planner. The public result has its own compact contract and does not expose private pipeline state.

HTML preparation is an explicit replaceable/bypassable JSON step. It produces parsed, cleared HTML using extraction's parser. Originals remain unchanged for extraction/trials. XML stays original text until selection; JSON stays native. Query/format mismatches and ordinary selector/field errors become mechanical feedback; cancellation, integrity and resource failures remain terminal.

Source inspection reads already-owned current-frontier data. Windows bound displayed evidence, not actual extraction. Oversized markup is omitted explicitly rather than cut into a misleading partial tree. Complete captured trials execute the actual combined artifact against owned captures; the fresh URL trial is separate transport work under the artifact ceilings.

Inspection has one strict shape: `{action:"inspect",source,query,window:{offset,limit}}`. The window is required; it is never silently replaced by a one-element display. HTML queries use CSS and optional dynamic fields; XML queries use the existing XPath contract. Cortex owns schema correction.

Before an HTML source-author call, JSON constructs a real HTML view. A fitting prepared document is shown whole; otherwise the shared html-model-view helper uses the configured initial inspection and explicit continuation. One `author.html` job can inspect or propose the complete current source rule, including extraction, fields, navigation and resource references. Failed trials retain their actual feedback and current rule; they cannot restrict the next HTML proposal to navigation while extraction stays broken. The separate HTML selection/navigation/processing operations and candidate schemas are deleted. Every model call and Cortex correction charges the same author pool; failed or empty inspections never force a proposal. A source with no displayable HTML does not trigger an author call.

An initial proposal with null extraction, navigation and resource selection receives `SOURCE_RULE_EMPTY` feedback within that same source job and allowance. This rejects an unfinished proposal, not a learned selector returning no current matches. HTML selection also projects configured URL-valued fields/attributes into additive `references` metadata using existing `url.resolve`; raw selections remain intact. The shipped HTML profile configures `href`, while omission disables projection. Captured shaping input and published execution share that JSON helper. See `docs/plans/source-rule-url-references.md` for the contract.

The shared JSON `level-sources` helper receives only `{level,owned,captures}` and derives offers from the current level's URL and captured-body hash, selecting one current owned representative per capture. Traversal materializes that frontier once for the source job; request and inspection use the same supplied authority and original indices. The redundant `frontier-sources` whole-state wrapper is deleted. Retained repair captures do not duplicate source messages or make stale indices available.

With `observations.skipRepeated:true`, an exact repetition of the latest inspection on the same owned URL/hash reuses its observation and reports `repeated:true`. Query fields and window participate in equality. A different inspection can return to an earlier window; no all-history prohibition or persisted cache is involved. The existing author allowance still bounds calls.

With `observations.useScopedHtml:true`, a successful nonempty HTML inspection supplies the matching source's next model view as whole prepared subtrees. The view is explicitly partial; count/range/omission/field facts appear once in the active HTML view metadata, and other frontier sources remain visible. Failed, empty and fully omitted inspections use the shared initial view rather than a body-free manifest or an oversized fallback. XML inspection feedback retains its native selected values. The author can inspect another region of the same owned source. Original captures and complete mechanical trials are unchanged; XML still supplies original XML.

Own-job history keeps actions, failures and observation facts without expanded historical HTML. The active HTML is supplied once as source evidence; an identical observation already supplied as current feedback is omitted from rendered history. This changes neither permissions nor retry allowances, and does not guarantee semantic completeness or force a candidate.

Charged acquisition history, aliases and resources survive local proposal retries. Traversal reuses existing mechanical helpers. No database, ledger, persisted state or duplicate native crawler is added.

## HTML preparation and large frontiers

Preparation retains parsed document declarations, including public/system identifiers, so serialization does not change legacy parsing mode. The round-trip integrity check remains mandatory. Default policy clears script/style payloads, inline code/style values and the explicitly excluded SVG interiors; it preserves class names, data attributes, metadata and other potentially requested document regions. Native reader defaults admit 2 MiB and 20,000 elements.

The shared JSON html-model-view helper allocates the existing observation/HTML display allowance across offered sources. It shows a full prepared document only when its encoded value fits; otherwise htmlContext.initialInspection defaults to selector \*, offset 0/limit 20,000 and omitNested:true. This scans through the default reader's admitted element range rather than stopping inside the first head tags. It includes only whole subtrees that fit the unchanged byte allowance; included parents already contain their descendants, so those descendants consume neither another HTML copy nor another serialization. This is a display window, not an extraction cap or relevance classifier. Metadata includes the count of covered descendant matches, skipped oversized subtrees and continuation. If no subtree fits but nextOffset exists, JSON advances before calling a model. Explicit scoped inspections with dynamic fields retain each displayed record's field associations; fieldless inspections suppress already covered descendants. Rendering joins those bounded fragments directly, without a pairwise ancestor search. A genuinely impossible display is explicit unavailability, not permission to invent a selector. The complete request guard remains a separate safety boundary; bounded HTML views replace whole-page review inputs.

Successful source trials do not encode full unused rejection feedback or fail its observation ceiling. Rejected trials remain bounded.

The reviewer uses the same HTML view helper. After inspection, fitting full prepared HTML remains visible once alongside the inspection query, fields and range, provided their combined encoded evidence fits the existing per-source allowance. Oversized sources retain bounded scoped views and explicit continuation. Inspection ending does not mean the whole source ended. Source-author scoped-view behavior is unchanged. Its response is an HTML inspection request or the existing accepted/reason verdict. Review inspection is scoped to already-owned evidence, performs no HTTP and cannot expand caller permissions. The fixed JSON review-turn loop preserves its own proposal/observation history, charges Cortex recovery steps/time/usage cumulatively, and returns explicit unavailable review when no verdict or HTML can be obtained. Working artifacts remain usable after negative or unavailable review, subject to the unchanged fresh mechanical trial.

## Budgets and public outcomes

The default JSON profile supplies:

```json
{
  "author": { "maxModelSteps": 12, "maxResponseAttempts": 3, "maxModelMs": 300000 },
  "review": { "maxModelSteps": 4, "maxModelMs": 60000 },
  "observations": { "maxBytes": 262144, "useScopedHtml": true, "skipRepeated": true },
  "maxInputBytes": 524288
}
```

Task/source/schema/Prism calls and their Cortex recovery share the current attempt's author allowance. Per-invocation recovery is bounded by the remaining allowance; phase changes do not reset it. Reviewer calls and Cortex recovery share the current attempt's review allowance. Each bounded review-driven attempt starts fresh author and reviewer allowances; phases and local mechanical retries do not refresh them. Captures and whole-discovery page/resource charges never reset. The configured whole-run engine cap and caller cancellation remain authoritative. During repair, JSON permits recovery of declared HTTP status/transport failures; a separate unrecorded check stops errors outside that allowlist, including integrity and XML resource-limit failures. HTTP provider attempts and actual rate-limit waits are transport observations, not additional review passes or preemptive reservations. Byte limits are not tokenizer guarantees.

Discovery exposes `status`, `artifact`, `reason`, `outputSchema`, `trial`, `partialTrial` and `blocked`. Unresolved has a null artifact and concrete reason. Exhausted configured provider rate limits instead return `blocked`; a previously working artifact survives blocked review or repair as `ready` with provider facts. Transport retries resume the same request under the original model and caller time limits; JSON owns their count/status/fallback policy. They never restart authoring, refetch its owned page or grant a new allowance. Cooldown is scoped to one factory client/model, not independent processes. Partial trial data is a schema-matched captured whole-bundle diagnostic, not a published artifact. The final fresh trial may be null when it was never reached. Valid intermediate proposals are not publication.

## Engine admission and static binding

Discovery defaults to best effort. HTML authors choose selectors, reads, navigation and declared processing; they do not author page preconditions or field match bounds. JSON supplies `preconditions:[]` and `authoring.fieldBounds` (default minimum zero, maximum null) before measurement, trials and storage. The retired conditions-author path is deleted. Overlapping records are permitted by the default authoring profile; existing review can explain their quality impact. Invalid selectors/programs, permissions, integrity and resource controls remain enforced.

For automatically generated schemas, the original schema must first compile. JSON then makes object properties optional and nullable recursively, preserving their non-null types, array structure and associations. That one resulting schema is used for shaping, review, trials, publication and returned `outputSchema`. Caller schemas bypass this normalization and remain unchanged. A request for ten records is an upper target; nine usable records or an unavailable field must not become an invented execution gate. Negative review and failed review-driven corrections retain a working artifact as before.

Explicit preconditions and field bounds in existing executable artifacts retain their behavior. The execution grammar/readers and engine have not been weakened; discovery simply stops inventing those hard requirements.

The existing `eden.engine:1` grammar supports literal `artifact.data`, pure `{id,value}` steps and expression-valued check names. Literal data is never executed as a program. Prism expressions compile before effects; computed failure names evaluate only for failed checks.

Structural Zod parsing is not executable admission. `prepareArtifact` resolves Strata stamps, all operation/helper references and JSON Schemas, then compiles Prism expressions, including inactive/unused helpers. Native operations validate their own boundaries; run limits, cancellation and source integrity remain enforced.

The binder composes whole static helpers and literal learned rules. Learned Prism programs become admitted executable helper outputs, not runtime evaluation of data or positional AST rewriting. Emitted artifacts carry their own derived contracts and require no discovery import or model capability during execution.

## Verification boundary

The approved narrow contract is in [job-specific discovery](../plans/job-specific-discovery.md). Offline tests and reviews establish mechanics/ownership, not that 120b learns good rules. The source-ownership refactor preserves 787 recorded events exactly: 95 public outcomes, 447 controlled model inputs including exact messages/settings, and 245 top-registry HTTP-operation inputs. These are frozen-control preservation checks, not paid model requests or a new accuracy score. Any future accuracy claim needs its own evidence; no new paid-model release gate is introduced. The older universal-controller proposal failed adoption; its dated plan, reports and failed trials remain historical and must not be restored as current policy.
