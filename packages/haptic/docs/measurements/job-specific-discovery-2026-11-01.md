# Job-specific discovery: implementation and focused evidence

The approved narrower pipeline is implemented and the universal conversational controller is deleted. **This corrected the model interface; it did not demonstrate improved semantic discovery accuracy.** Six frozen cases produced three complete results, one useful partial and two unresolved results, the same categories as the earlier pipeline on those cases. A separate reference-input correction made that program executable but still did not produce a verified PDF artifact. No broad batch followed.

## Ownership and deletions

The root JSON flow now admits the request/schema, declares the allowed task, traverses sources, observes extraction, declares an automatic schema when needed, authors a bare Prism program, reviews shaped data and performs a fresh mechanical trial. Source, schema, mapping and review jobs receive distinct inputs. Mapping receives native data, result schema and current mapping feedback, without source bodies or a conversation transcript.

Deleted `author-actions.ts` and its universal response protocol, model finish calls, arbitrary component/value inspection, history replay, generated-schema reconsideration, repeated semantic review, revision/invalidation state, obsolete assembly caching and redundant inspection branches. Source inspection is restricted to current owned HTML/XML sources. Typed component contracts, local mechanical repair, captured trials, original-format evidence and runtime bindings remain. Semantic rejection is unresolved rather than a guessed global repair.

`source-author.ts` registers typed capabilities; it does not select jobs or validate semantic policy. The JSON profile/workflow owns settings, ceilings, branching and repair. Thin internal schemas now reject unknown source jobs and budget owners before effects, without introducing another full state grammar. A search consumer now counts `resources.items`, matching the public resource envelope; the old test incorrectly supplied an array directly.

All eleven engine files, the Cortex model adapter and the dependency lock are byte-identical to the preserved previous candidate. No sibling workspace was changed or linked. There is no database, mandatory persistence or execution AI.

The JSON orchestration remains verbose: approximately 113 KB of compact JSON. Removing the universal interaction does not justify calling the whole implementation minimal or claiming every reviewer graded it 9/10.

## Snowdrop research

Read-only investigation used the actual latest experiment, `niscorp/.claude/worktrees/snowdrop/apps/lab/snowdrop-poc/data/professional-365d/memory/propagate-28d-v2.md`, and its `src/memory/propagate.ts`, model adapter and Jev adapter. The package itself still describes contracts, not a completed runtime.

The experiment batches evidence-backed statements in one Jev request, then gives 20b one summary-edit job per thing, returning `{keep,add}`. It reports 179 completed replay runs, 625 logical edits and 369 changed summaries; 695 Cortex invocations include failed/repeated work, with 90 corrections and 14 invocations exhausting recovery. Its median completed-run time is 1.3 seconds. These are not independently graded summary-accuracy results, and the invocation count is not an audited raw provider-request count.

The useful transfer is one small job with a named product and relevant evidence. It does not establish that 20b or Jev can write Haptic's selectors or Prism programs. The comparison therefore retains 120b, high reasoning, temperature 1, top-p 1 and emit. No Snowdrop storage, graph, queue or native decision code was copied.

## Reference-frame diagnosis and separate follow-up

The failed reference programs repeatedly read `$.items`, `$` or an example-array index, while the engine exposes selected values under `$.input`. Offline evaluation of the actual saved link expression succeeds on the bare selected value and fails on `{input: selectedValue}`. The initial model context displayed bare values in an example array. Its system instruction mentioned `$.input`, but the displayed examples did not show that execution scope.

The existing JSON step now displays independent `{input: sourceValue}` program contexts explicitly and clears unrelated XML selection feedback on the handoff. Original selected values and runtime binding are unchanged. An independent contract reviewer verified the producer-to-consumer match; offline JSON/XML reference tests pass, including failed first programs, stable retry input, changed/added/empty records and namespace changes. A separate diagnostics correction preserves the last failed program/trial when allowance ends.

One fresh repeat of the identical PDF case used **five requests, 35,531 input / 13,984 output tokens and 33.969 discovery seconds** (34.561 seconds total). The reference program now uses `$.input.items`, passes its actual stage trial and follows the article link. The HTML stage also passes. Complete acquisition nevertheless stops because the model inferred `https://arxiv.org/pdf/1706.03762v7.pdf`, which is absent from the frozen response graph. No live response was substituted. This proves neither that the inferred URL is invalid on the live web nor that the resource task works. No artifact was published and the original six-case results remain unchanged.

Evidence: `data/runs/reference-frame-proof-2026-11-01/`. All five provider requests succeeded with reported usage, zero waits and zero execution AI. Across both paid experiments: 37 requests, 507,390 input / 93,897 output tokens, 252.374 seconds total.

## Engineering verification and reviews

### Subsequent independent live PDF alias diagnosis

After the owner challenged the aggregate interpretation, the existing mechanical engine fetched both the inferred `https://arxiv.org/pdf/1706.03762v7.pdf` and source-observed `https://arxiv.org/pdf/1706.03762v7` live, with zero model calls or production changes. The inferred URL returned 301 to the observed URL; both completed HTTP 200 with the same 2,215,244-byte `%PDF-1.5` document and SHA-256 `bdfaa68d8984f0dc02beaca527b76f207d99b666d31d1da728ee0728182df697`. Measured execution was 419.139 ms through the alias and 73.022 ms directly. The previously missing response was therefore a valid redirect absent from the frozen fixture, not a demonstrated bad download URL. Original frozen results remain unresolved and unchanged; this probe does not finish schema/mapping/review/publication or certify a returned complete resource artifact. Evidence: `data/runs/pdf-alias-diagnosis-2026-11-01/`. There were no saved-page substitutions.

- `pnpm typecheck` and the full `pnpm check` pass. The focused mechanics comprise 59 groups across discovery, acquisition, source inspection, captured trials/resources/assembly, source contracts, actual search composition and local Cortex HTML-record checks. Normal checks include fifteen benchmark-support tests.
- Isolated package consumption passes with real historical returned artifacts: two artifacts, four executions, zero execution model imports; optional discovery/search/codec entries remain separate. This is packaging evidence, not new model accuracy.

## Assessment

Keep the clear job contracts, runtime-aligned reference examples, original mechanics and deleted controller. They address concrete ownership/interface defects. Do not claim the library is finished or that these experiments improved semantic accuracy. The remaining evidence is specific: premature title filtering loses contextual records, a reviewer can accept incomplete output, empty/changed HTML can expose a non-reusable mapping, and a resource program can infer an unverified target. There was no additional prompt campaign, model switch or broad paid batch after the scoped follow-up.
