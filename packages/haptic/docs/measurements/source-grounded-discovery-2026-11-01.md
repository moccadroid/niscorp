# Source-grounded discovery: implemented, adoption gate failed

The owner approved the complete target in `docs/plans/source-grounded-discovery.md`, its implementation, checkpoint reviews and a frozen comparison. The replacement is implemented in the checkout. **Do not treat it as adopted or ready to release: the measured model interface failed the predeclared quality gate.** No prompt, model, schema, instruction or candidate was manually corrected during the paid batches. Paid work stopped after the second candidate case; ten candidate cases remain untested.

## Implementation and engineering verification

The JSON workflow owns phases, focus, observations, component replacement, invalidation, acquisition allowances, aggregate model budgets, final review and publication. TypeScript owns typed model boundaries, schema documentation, source mechanics and inspection. Models author rules/programs during discovery; finished execution has no model operations or credentials.

Implemented boundaries include source proposal observations before readiness; conditions-only correction; revisitable generated contracts after source grounding; immutable caller schemas; charged acquisition separate from the current proposed walk; actual complete captured-bundle trials; one bounded final reviewer; a separate fresh mechanical trial; concrete unresolved reasons and schema-matched partial trial diagnostics. ## Why the candidate failed

Exact requests/responses and system components are preserved in `candidate/output-interface-evidence.json`. A separate model-interface critic reviewed them after the gate stopped, without edits or further model calls.

1. **A specialized program-writing job became an overloaded authoring job.** Baseline's mapping instruction explicitly said the answer must be the program, never its result, and labelled the desired result schema as not the model's response. Candidate used one shared HTML/XML/navigation/resource/repair/Prism prompt, an action/Prism guide with no `OUTPUT SCHEMA` heading, and a final context containing the result schema under the generic key `schema`. Cortex's finish protocol still referred to `OUTPUT SCHEMA`. The runtime validator remained correct, but its model-facing presentation was confusing.
2. **Retained state was confused with context needed in every call.** Candidate's first output call resent all 267,829 characters of prepared HTML, prior selected records, those records again as native input, current rules/schema and 35,355 characters of action/Prism documentation. It used 88,934 input tokens versus 8,985 for baseline's first mapping call. Six unsuccessful output responses consumed 539,007 input tokens; source calls consumed 486,654, and schema generation 81,201.
3. **Recovery explained only structure.** Cortex correctly reported `data: Invalid input: expected object, received array`. All six successful output responses repeated the four concrete events. It could not recover the distinction between answering the question and writing the program from that structural error.
4. **The original relevance omission remained.** Source authoring still chose titles containing `AI`, losing the event supported by organizer context. No source call requested inspection. Successful mechanical observations alone did not make the model choose a complete reusable rule.

The measured candidate total was 183.78 seconds: 79.65 seconds inside provider intervals, 101.10 seconds of actual rate-limit gaps and 3.03 seconds unprofiled remainder. The latency regression was driven by oversized repeated model input and actual quota waits; it was not slow finished-artifact execution. These categories are measured intervals, not an isolated CPU profile.

## Critical assessment and recommendation

The engineering work establishes explicit ownership, source-aligned trials, local edits and safe publication gates. It also removes obsolete paths instead of retaining aliases. These are useful mechanical properties.

**The attempted model interface is a regression and should not be adopted.** It costs more input, returns fewer useful artifacts and does not repair the original semantic omission. Passing offline checks or receiving near-nine engineering grades does not offset that result.

Retain the engine and mechanical correctness improvements. Reject the universal all-format prompt, the generic action wrapper as the Prism-writing interface, and full transcript/source replay as semantic continuity. A subsequent design should keep evidence in JSON state while giving each model invocation one explicit job and the relevant input. Existing standalone program-authoring contracts are the demonstrated comparison point. This is a model-boundary redesign recommendation, not permission for another prompt-tuning batch, another judge, more retries or a larger model.

The present checkout remains the rejected candidate for inspection; no package move/release, silent rollback, compatibility path or further paid campaign was performed. A new implementation/experiment decision is required before continuing.
