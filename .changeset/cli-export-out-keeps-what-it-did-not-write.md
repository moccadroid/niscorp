`nisc export --out <dir>` no longer empties the folder it is given. It removes only the files the previous export wrote there, recorded in `node_modules/.cache/nisc/exports.json`, then writes the new export; everything else in the folder (a `.git`, a notes file) stays and is named on one line each run. The default `out/` is emptied as before, also when named with `--out out`. Removal goes by real location: a link in the folder is removed as a link and never written or deleted through, and `--out` is refused when where it points is the app, above it, or the build. The export is first written into a fresh folder, so a file that cannot be made changes nothing. What changes for a folder named with `--out`: files an older export left there, before the record or without it (a fresh CI checkout), are named on every run instead of removed; a file another step put in the folder survives the next export; a link named with `--out` is written into, where it used to be replaced by a folder; a file at the `--out` path, or a folder with files of its own where the export writes a file, is said and nothing is written, where both used to be replaced.
